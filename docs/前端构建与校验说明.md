# 前端构建与校验说明

> 适用版本：Vite 8.3.6 + Vue 3.5 + ant-design-vue 4，Node >= 20.19。
> 本文说明 `frontend` 下的构建流程、四条产物校验和真机冒烟脚本各自的作用、失败含义与处理方式。

---

## 一、命令速查

所有命令都在 `frontend` 目录执行。

| 命令 | 做什么 | 需要 8080 | 耗时（参考） |
|---|---|---|---|
| `npm run dev` | 启动 Vite dev server（`http://localhost:5173/app/`），`/api` 代理到 8080 | 是（只代理接口） | 秒级 |
| `npm run build` | **构建 + 同步 target + 四项校验**，任一失败即退出非 0 | 否 | 约 2–3 s |
| `npm run build:pure` | 只构建 + 同步，**不做任何校验**（逃生口） | 否 | 约 1 s |
| `npm run verify` | 校验（自己会先构建，再查产物） | 否 | 约 2–3 s |
| `npm run verify -- --no-build` | 只查现有产物，不重新构建 | 否 | 约 0.2 s |
| `npm run verify -- --smoke` | `verify` 全套 + 真机冒烟 | **是** | 约 1 min |
| `npm run verify:smoke` | 同上（等价写法） | 是 | 约 1 min |
| `npm run smoke` | 只跑真机冒烟 | 是 | 约 55 s |

**日常提交前只需 `npm run build`**；改了弹层加载方式、或要发版演示时，再跑一次 `npm run verify -- --smoke`。

## 二、`npm run build` 到底做了什么

```
vite build
  └─ 产物写入 src/main/resources/static/app
node scripts/sync-target.mjs
  └─ 覆盖 target/classes/static/app（8080 实际读取的位置）
node scripts/verify.mjs --no-build
  └─ 模板标签 → 引用完整性 → 循环依赖 → 弹层按需
```

三个必须知道的细节：

1. **产物目录是 `src/main/resources/static/app`**，不是 `target`。Vite 的 `base` 为 `/app/`，与 Spring Boot 的访问路径一致，不需要额外反代。
2. **`target/classes/static/app` 只是同步副本**。直接改那里会在下次构建时被覆盖；`sync-target` 在 `target/classes` 尚不存在时会跳过并返回 0（首次 `mvn` 编译会从 resources 复制）。
3. **校验失败时产物已经被覆盖**，这份产物不可信，不要直接拿它启动 8080；先修复再 `npm run build`。

对应 `package.json` 中的定义：

```json
"build":      "vite build && node scripts/sync-target.mjs && node scripts/verify.mjs --no-build",
"build:pure": "vite build && node scripts/sync-target.mjs",
"verify":     "node scripts/verify.mjs"
```

### 为什么 `build` 和 `verify` 不互相调用

`verify` 自己会执行构建；如果 `build` 再调用完整的 `verify`，就会形成递归构建。因此 `build` 调用的是 `verify.mjs --no-build`，只做产物检查。

### `build:pure` 的使用边界

它绕过全部校验，仅在「校验脚本自身出问题导致无法出包」时使用。使用者必须已经确认产物无误、并且清楚为什么绕过——循环依赖导致的白屏在编译期完全看不出来，这正是校验存在的理由。

## 三、四条产物校验

| 脚本 | 检查内容 | 失败意味着 | 处理方式 |
|---|---|---|---|
| `check-antd-tags.mjs` | 扫描所有 `.vue`，确认每个 `a-xxx` 标签都能被 `vite/antd-subpath-resolver.js` 解析 | 模板里用了 resolver 未登记的组件 | 在 `COMPONENTS` 里加一行映射 |
| `verify-assets-refs.mjs` | 遍历 `assets/*.js` 的 `import` / `import()` 目标，确认文件都存在 | 存在指向已不存在 chunk 的引用（多为旧 `index.html` 或残留产物） | 重新完整构建；仍失败则检查是否有手写引用 |
| `check-chunk-cycles.mjs` | 按 chunk 的静态/动态 import 边做 DFS 找环 | 存在 chunk 级循环依赖 | 去掉 `vite.config.js` 里人为的 `codeSplitting.groups` |
| `verify-async-chunks.mjs` | 确认 4 个列表页引用的 5 个弹层组件（共 9 处引用）都产出独立 chunk、未被页面静态引用、且有 `default` 导出 | 弹层被写回静态 import，或丢失 default 导出 | 恢复 `defineAsyncComponent` + `v-if` 门控 |

### 1. 模板标签校验（构建前）

组件名写错**不会**让构建失败，只会在浏览器控制台出现 `Failed to resolve component: a-xxx`。这条校验放在构建前，能提前 2 秒拦住这类问题。

预期输出：

```text
扫描 .vue 文件数：16
解析成功组件：40
未解析标签：0
  ✓ 模板内所有 a-xxx 标签均可解析，无运行时未注册风险
```

它直接复用 `AntdSubpathResolver`，与构建时用的是同一份映射表，所以不会出现「校验过、构建错」的分歧。

### 2. 引用完整性

防止「构建目录里只剩一半文件」或「`index.html` 引用了已被替换的 chunk」。这类问题在浏览器里的表现是 404 + 白屏，而在产物目录里一条命令就能查出来。

### 3. 循环依赖

这是本项目踩过最贵的一次坑：把 `@ant-design/icons-vue` 单独拆成一个 chunk 后，它与 `vc-resize-observer` 互相引用，图标 chunk 先求值、antd 色板对象尚未初始化，`undefined['#f5222d']` 直接抛错，**构建完全成功、页面全白**。

所以：

- `vite.config.js` 里**不要写 `build.rollupOptions.output.manualChunks` / `codeSplitting.groups`**，交给 Rolldown 按模块图自动分块，求值顺序才有保证；
- 需要减小首屏，正确做法是**页面级懒加载**（路由 `() => import(...)`、弹层 `defineAsyncComponent`），而不是手工切三方库；
- 手工分组一旦重新出现，这条校验会立刻报出环，不必等到浏览器白屏。

### 4. 弹层按需加载

判定依据两条，缺一不可：

1. 目标组件**产出独立 chunk**（静态 import 时会被并进页面 chunk，连 chunk 都没有）；
2. 页面 chunk 里**不能有**对该 chunk 的静态 import，但**要能引用**到它（动态 import）。

期望清单：

| 页面 | 应按需的弹层 |
|---|---|
| 待办中心 `/todo` | TaskDrawer、ProcessTraceModal、TransferModal、DelegateModal |
| 我的已办 `/done` | ProcessTraceModal、DetailDrawer |
| 我的发起 `/started` | ProcessTraceModal、DetailDrawer |
| 委托记录 `/delegation` | ProcessTraceModal |

> **曾经的问题**：脚本早期对「未产出独立 chunk」只打印一行就 `continue`，导致把 `defineAsyncComponent` 改回静态 `import` 时校验照样通过（假绿）。现在这种情况**计入失败**。

输出里可能出现「另有静态引入者：TaskDrawer-…」，属于正常的「懒加载父带子」（`TaskDrawer` 内部使用 `TransferModal`、`DelegateModal`、`DetailDrawer`），这些子弹层仍不在首屏，脚本只提示、不判失败。

## 四、失败信息怎么读

`verify.mjs` 失败时会停在第一处并给出针对性提示：

| 输出 | 含义 | 下一步 |
|---|---|---|
| `校验未通过：check-antd-tags` | 有 `a-xxx` 无法映射 | 补 `vite/antd-subpath-resolver.js` 的 `COMPONENTS` |
| `校验未通过：verify-assets-refs` | 有 chunk 引用缺失文件 | 重新完整构建；检查是否残留旧产物 |
| `校验未通过：check-chunk-cycles` | 存在 chunk 循环 | 删除人为分组，改为页面级懒加载 |
| `校验未通过：verify-async-chunks` | 某弹层退回静态引入或丢 default | 恢复 `defineAsyncComponent` + `v-if` |
| `校验未通过：e2e-smoke（8080 未监听）` | 冒烟前置条件不满足 | 先启动后端，再重跑 |
| `✗ 缺少依赖：…/vite/bin/vite.js` | `node_modules` 不完整 | `npm ci`（先结束占用 node_modules 的 node 进程，否则 Windows 会 EPERM） |

成功时会打印当前入口文件名：

```text
全部通过
当前入口：index-X9cgiDCN.js（浏览器需 Ctrl+F5 强刷才会加载新哈希）
```

## 五、真机冒烟

### 前置条件

- 8080 已在运行（`verify --smoke` 会先探测端口，未监听直接报错，不会卡在超时里）；
- 演示数据里有至少一条待办（脚本用 `manager` 登录）。

### 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `SMOKE_BASE` | `http://localhost:8080/app` | 被测地址 |
| `SMOKE_USER` | `manager` | 登录账号 |
| `SMOKE_PASS` | `demo` | 登录密码 |
| `SMOKE_HEADED` | 空（无头） | 设为 `1` 时有头运行，便于肉眼观察 |
| `SMOKE_BROWSER` | `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe` | 浏览器可执行文件 |

脚本用 `playwright-core` 驱动系统 Edge，**不下载 Chromium**（省约 150 MB）。换机器时若 Edge 路径不同，用 `SMOKE_BROWSER` 指定。

### 覆盖的 6 项

| 项 | 校验内容 |
|---|---|
| 登录 → 待办 | 跳转 `#/todo`，列表有数据 |
| 待办详情抽屉 | 标题、标签、正文非空，无加载失败态 |
| 流程跟踪弹窗 | BPMN 节点与 SVG 正常渲染 |
| 转办弹窗 | 接收人列表加载，选中即止，不提交 |
| 委托弹窗 | 受托人列表加载，选中即止，不提交 |
| 子流程下钻 / 返回上级 | 无「已执行的调用子流程」时**跳过**（`○`，不算失败） |

### 两条脚本里已固化的坑

1. **antd 会给两字按钮插空格**：实际可访问名是「登 录 / 转 办 / 取 消」。写死 `'登录'` 永远匹配不到，脚本统一用允许空白的正则（`/登\s*录/`）。
2. **Escape 会冒泡关掉整个 Modal**：原本想用 Esc 收起下拉，结果弹窗一起关闭、「取消」按钮消失。现在改为点选下拉第一项让下拉自然收起，同时验证了候选人确实可选。

### 设计原则

- **只打开、只校验渲染，不点确认**：转办与委托会真实改变待办归属，冒烟脚本不应污染演示数据；
- 失败自动截图到 `frontend/scripts/e2e-shots/N.png`；
- Console 与 Network 分别过滤 `/api/auth/me`、`favicon`、`401`——这三项是未登录探测与站点图标的预期噪声，不算失败；
- 任一项失败即退出码 1，可直接接 CI。

### 补第 6 项的办法

需要一条**带调用子流程、且已执行到该节点**的实例：用 `applicant` 发起一条含子流程的流程并推进到调用节点，然后：

```powershell
$env:SMOKE_USER="applicant"; npm run smoke
```

脚本会在「下钻子流程 N 个」链接与图上蓝色徽标之间逐个尝试，进入后校验层级文字，再点「返回上级流程」确认退出。

## 六、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 8080 打开白屏，Console 有 `Cannot read properties of undefined (reading '#f5222d')` | chunk 循环依赖 | 去掉 `codeSplitting.groups`，重跑 `npm run build` |
| 8080 白屏，`index-*.js` 404 | `index.html` 被缓存，引用了旧哈希 | Ctrl+F5；确认静态资源的 `no-cache` 头 |
| 改了代码，8080 上没变化 | 没构建 / 没同步 target / 浏览器缓存 | `npm run build`，然后 Ctrl+F5 |
| 5173 白屏，报某个 `__XXX__` 未定义 | dev server 是升级前的旧进程，`@vite/client` 已被新版本覆盖 | 杀掉占用 5173 的进程，删 `node_modules\.vite`，`npm run dev -- --force` |
| Console 有 `GET /api/auth/me 401` | 受保护路由在探测登录态 | 预期行为；登录页已不再探测 |
| Console 有 `favicon.ico 404` | 缺少站点图标 | 已提供 `public/favicon.svg`，强刷即可 |
| `Failed to resolve component: a-xxx` | resolver 漏映射 | 补 `COMPONENTS`，或直接跑 `npm run build` 让校验报出 |
| Windows 上 `npm ci` 报 EPERM | 有 node 进程占着 `node_modules` | 先 `Get-Process node \| Stop-Process -Force` |

### 关于 `npm run dev`

- 访问路径必须带前缀：`http://localhost:5173/app/`；
- 遇到依赖升级后的白屏，先杀进程、删 `node_modules\.vite`、再 `npm run dev -- --force`；
- dev 不拆 chunk，**循环依赖在 dev 下看不出来**，所以不能只用 5173 验证产物问题。

## 七、维护约定

### 新增一个 antd 组件

只在 `frontend/vite/antd-subpath-resolver.js` 的 `COMPONENTS` 里加一行映射，例如：

```js
'Tag': { from: 'ant-design-vue/es/tag' },
'MenuItem': { from: 'ant-design-vue/es/menu', name: 'MenuItem' }
```

**不要**改用官方 `AntDesignVueResolver`：它生成的 import 全部指向聚合入口 `ant-design-vue/es`，所有页面共享同一 module，分包时会被提升成一个大公共 chunk，等于白做按需。

漏加不会让构建失败，但 `check-antd-tags` 会报出、浏览器控制台会报 `Failed to resolve component`。

### 新增一个弹层（抽屉 / 弹窗）

必须同时满足三件事，否则 `verify-async-chunks` 会失败：

```js
// 1. 异步引入
const MyModal = defineAsyncComponent(() => import('../components/MyModal.vue'))

// 2. 用 v-if 门控，首次打开前不挂载
const myMounted = ref(false)
function openMy() {
  myMounted.value = true      // 3. 打开函数里先置 true
  visible.value = true
}
```

```html
<MyModal v-if="myMounted" v-model:open="visible" />
```

**为什么必须配 `v-if`**：只写 `defineAsyncComponent` 而不用 `v-if`，组件在页面挂载时就会渲染（只是 `open=false`），异步 chunk 立刻被下载，等于没做懒加载。

**配套注意**：加了 `v-if` 后，组件首次渲染时 `props.open` 已经是 `true`，`watch(() => props.open)` 不会触发。子组件里必须写 `{ immediate: true }`，否则会出现「弹窗打开了但数据不加载」。这一行容易被后来人当成冗余删掉，建议在调用处写注释说明。

**关闭后不要卸载**（`myMounted` 保持 `true`）：chunk 只下一次，`a-modal` / `a-drawer` 的关闭动画也不会被 `v-if` 打断。

### 新增页面

- 路由用 `() => import('../views/XxxList.vue')`，页面级懒加载是减小首屏的正道；
- 页面里的弹层按上一节处理；
- 如果该页面也要纳入按需校验，在 `verify-async-chunks.mjs` 的 `expectations` 里加一行（页面 chunk 前缀 + 期望的弹层前缀）。

### 不要做的事

| 禁止 | 原因 |
|---|---|
| 写 `build.rollupOptions.output.manualChunks` / `codeSplitting.groups` | 极易制造 chunk 循环依赖，白屏且编译期无感 |
| `import { message } from 'ant-design-vue'` | 会拉入聚合入口；用 `ant-design-vue/es/message` |
| 直接改 `target/classes/static/app` | 构建时被覆盖 |
| 忽略 `build` 的非 0 退出码 | 产物已被覆盖且不可信 |
| 用 5173 验证产物问题 | dev 不拆 chunk，看不到循环依赖 |

## 八、典型工作流

**日常改业务代码：**

```bash
cd frontend
npm run build          # 构建 + 校验，失败即修
# 浏览器 Ctrl+F5 强刷 8080
```

**排查「白屏 / 点了没反应」：**

```bash
cd frontend
npm run verify         # 先确认产物本身没问题
# 若产物 OK，再看浏览器 Console 与 Network
```

**发版前：**

```bash
# 后端已启动在 8080
cd frontend
npm run verify -- --smoke
```

**急着出包、且确认只是脚本自身异常：**

```bash
npm run build:pure     # 绕过全部校验，慎用
```
