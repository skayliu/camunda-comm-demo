## 01 一条总规则：知道用传阅，办事用阅办

| 能力 | 一句话定义 | 接收方 | 是否要结果 |
|---|---|---|---|
| **传阅** | 让他知道，看完就行 | 待阅人 | 不需要，只记已读 |
| **阅办** | 让他办，但不由他拍板 | 承办人 | 需要，须反馈办理结果 |

两者的共同点必须记住：**都不创建 userTask、都不进流程变量、都不阻塞流程流转**。传阅的已读、阅办的办理结果都只落业务表，不会触发任何引擎动作。

一句话：**传阅是抄送的正名，阅办是承办的正名；「抄送」这个词在界面上不再出现。**

| 因流程驳回、撤回或结束而不再有效 | 已失效 | 状态列、统计卡副文案 | ~~已作废~~、~~已取消~~、~~已过期~~ |

**「我的待阅」与「我的传阅」是一对，不是同义词**：待阅是接收方视角，传阅是发起方视角。写文案时先想清楚这句话是给谁看的。

## 03 传阅与阅办的边界

| 维度 | 传阅 | 阅办 |
|---|---|---|
| 发起入口 | 审批抽屉「传阅」按钮、流程节点自动触发、流程结束自动触发 | 审批抽屉「阅办」入口，由审批人 / 发起人 / 管理员指定承办人 |
| 接收方称呼 | 待阅人 | 承办人 |
| 接收方要做的事 | 打开看，必要时点「标已读」 | 开始办理 → 填写办理结果 → 提交 |
| 有无时限 | 无 | 有，`deadline` 可为空（不限期） |
| 有无结果 | 无，只有已读时间 | 有，`handleResult` + `handleTime` |
| 能否撤回 | 本人发出、对方未读、未撤回 | 本人发出、未提交结果、未撤回 |
| 已读 / 已完成后能否撤回 | 不能，已读是送达证据 | 不能，结果是承办人的履职证据 |
| 是否影响流程 | 完全不影响 | 完全不参与引擎决策，报告结果由流程侧自行取用 |
| 逾期 | 无此概念 | 超过 `deadline` 实时算逾期 |

一条判定：**对方需要「交东西」就是阅办，只需要「知道」就是传阅。** 两者混用会让撤回规则、状态词、指标卡全部说不通。

## 04 类型标签：三种传阅

| 类型标签 | 枚举值 | 触发方式 | 标题兜底 | 说明 |
|---|---|---|---|---|
| **节点传阅** | `NODE` | 某个审批节点结束时，按 BPMN 扩展属性自动发 | 节点名 | 最常用的自动传阅 |
| **流程传阅** | `INST` | 整个流程结束时统一发 | `流程传阅 · <流程key>` | 用于存档告知 |
| **手动传阅** | `MANUAL` | 审批过程中由审批人或发起人临时添加 | 取流程标题 | 弹层里发起的就是这一类 |

口径要点：

1. BPMN 里写 `AFTER_NODE` 与 `NODE` 等价，服务端会归一化为 `NODE`，所以标签只出现「节点传阅」一种，不出现「节点后传阅」。
2. 类型名由后端统一映射（`CcService` / `CcHandleReportService`），**历史数据无需刷库**，打开页面即显示新名称。
3. 禁止写成「节点抄送」「手动抄送」「流程抄送」，也禁止简化成「自动传阅」「手动传」——三者是并列枚举，不能只改一半。
4. 列名统一叫「**传阅类型**」，不要只写「类型」：单独一列「类型」在报表页有「传阅类型分布」对照时容易判为两个叫法。

## 05 状态词对照

### 5.1 传阅（`BizCcRecord`）

| 界面词 | 数据依据 | 含义 | 不能写成 |
|---|---|---|---|
| 未读 | `READ_ = 0` 且未撤回 | 已送达，未打开 | 未查看、待阅、未处理 |
| 已读 | `READ_ = 1` | 打开过，记 `READ_TIME_` | 已查看、已阅、已确认 |
| 已撤回 | `REVOKED_ = 1` 且 `REVOKE_REASON_ = 'REVOKED'` | 发送人主动收回 | 已删除、已作废、已取消 |
| 已失效 | `REVOKED_ = 1` 且 `REVOKE_REASON_ = 'INVALID'` | 流程驳回、撤回或结束导致 | 已过期、已终止、无效 |
| 已撤回 / 失效 | 统计卡合并口径 | 两类都算终止，单列一项 | 异常、失败 |

已读率口径：**已读 ÷ 已送达，撤回与失效不计入分母**。这决定统计卡不能写成「已读 / 总数」。

### 5.2 阅办（`BizHandleRecord`）

| 界面词 | 数据依据 | 含义 | 不能写成 |
|---|---|---|---|
| 待办理 | `HANDLE_STATUS_ = 'PENDING'` 且未逾期 | 已送达，承办人未开始 | **待阅**、未开始、待处理 |
| 办理中 | `HANDLE_STATUS_ = 'HANDLING'` | 承办人已开始 | 处理中、进行中 |
| 已逾期 | 未完成且 `DEADLINE_ < now` | 超过时限，实时推算 | 超时、延期、过期 |
| 已完成 | `HANDLE_STATUS_ = 'DONE'` | 已提交办理结果 | 已办理、已办结、已反馈 |
| 已撤回 | `REVOKE_REASON_ = 'REVOKED'` | 发起人主动收回 | 已取消 |
| 已失效 | `REVOKE_REASON_ = 'INVALID'` | 流程结束等导致 | 已终止 |

**最容易写错的一处**：`PENDING` 的界面词是「待办理」，不是「待阅」。代码注释里曾把它写作「待阅」，与「待阅人」撞词——一旦在阅办页面写「待阅」，用户会以为这是传阅的未读状态。

逾期口径：**由办理时限实时推算**，不依赖定时任务是否刚扫过；因此筛「已逾期」与表格里的逾期标签必须来自同一套判断，不能一处读库、一处查任务。

## 06 位置速查

### 6.1 我的待阅（接收方）

| 位置 | 必须这么写 |
|---|---|
| 菜单 / 面包屑 / 页面标题 | 我的待阅 |
| 页面说明 | 传阅副本已送达，仅可查看；阅读不影响流程流转，也不会进入审批待办 |
| 页头操作 | 批量标已读 / 刷新 |
| 搜索占位符 | 搜索标题、发送人 |
| 筛选 | 未读 / 已读 / 已撤回 / 全部（默认未读） |
| 表头 | 标题 / **传阅类型** / 发送人 / 传阅时间 / 状态 / 操作 |
| 状态标签 | 未读 / 已读 / 已撤回 / 已失效；标签下副行写「流程进行中 / 流程已结束」 |
| 行内操作 | 查看流程 / 标已读 / 撤回（仅 `canRevoke` 时出现） |
| 撤回确认 | 撤回这条传阅？ |
| 空状态 | 暂无待阅的传阅 |

「标已读」是单条动作，「批量标已读」是多选后的动作，两者都**不改流程状态**，只是把 `READ_` 置 1。

| 批量操作 | 撤回未读（同一个事务内完成，不撤一半） |
| 展开行 | 传阅明细 · **待阅人** / **传阅类型** · 节点 / 发送时间 / 状态 / 单条撤回 |

### 6.4 操作弹层与报表

| 位置 | 必须这么写 |
|---|---|
| 抽屉按钮 / 悬停提示 | 传阅 / 仅当前待办处理人可传阅 |
| 弹层标题 | 传阅（送达即可，不阻塞流程） |
| 弹层字段与占位符 | 待阅人 / 选择待阅人 |
| 弹层主按钮 | 发起传阅 |
| 弹层提示条 | 待阅人只能查看，没有同意、拒绝等审批权限 |
| 未选人校验 | 请选择待阅人 |
| 成功提示 | 已传阅 N 人，跳过 M 人（已有未撤回的传阅） |
| 报表菜单 / 标题 | 传阅与承办统计 |
| 报表页签 | 传阅分析 |
| 报表指标与图例 | 有效传阅 / 未读传阅 / 传阅 |
| 报表排行 | 谁传阅给谁（按传阅条数排序） |
| 报表空态 | 暂无传阅记录 |

成功提示里的「跳过 M 人」口径要说清：跳过的判断是**该人是否已有未撤回的传阅**，所以已撤回的人可以再次传阅。不要写成「已传阅过」，那会让人以为是永久拦截。

## 07 撤回口径

### 7.1 传阅撤回的三条硬约束

| # | 约束 | 越界时提示 |
|---|---|---|
| 1 | 只有发送人本人可撤回 | 只有发送人可以撤回传阅 |
| 2 | 对方必须未读 | 已读的传阅不能撤回（不提供入口） |
| 3 | 记录必须未撤回、未失效 | 传阅状态已变化，请刷新后重试 |

按流程批量撤回时，三条约束逐条生效，且在**同一个事务**内完成；只要有一条不满足就整批回滚，不出现撤一半的状态。已读的一律不给撤回入口——它是送达证据，撤回会让审计说不清楚。

### 7.2 阅办撤回

| 条件 | 结论 | 越界时提示 |
|---|---|---|
| 本人发出、未提交结果、未撤回 | 可撤回 | — |
| 已提交办理结果 | 不可撤回，保留承办人的履职证据 | 该阅办已完成，无需重复提交 |
| 已逾期但未提交 | 可撤回，逾期不是完成 | — |
| 已失效 | 无操作入口 | 该阅办已撤回或已失效 |
| 非本人发出 | 不可撤回 | 只有发起人可以撤回阅办 |

另外「不能把阅办派给自己」（`assignee = sender`）与「该承办人已有未完成的阅办」（去重）属发起侧校验，措辞同样要带上「阅办」二字，不要只说「记录」。

### 7.3 撤回后的展示

撤回与失效都是**软删除**：记录保留在库里留痕，列表里以「已撤回 / 已失效」呈现，不物理删除。因此任何文案都不要写「删除」「移除」。

## 08 代码层不跟文案改名

界面统一叫传阅，**内部标识一律不动**。改这些会打断接口、BPMN 模型和既有数据：

| 类别 | 保持不变 |
|---|---|
| 类名 | `BizCcRecord`、`BizHandleRecord`、`CcService`、`CcController` |
| 表与字段 | `BIZ_CC_RECORD_`、`CC_USER_ID_`、`SENDER_USER_ID_`、`READ_`、`REVOKED_` |
| 接口 | `/api/cc/**`、`/api/handle/**` |
| 入参与变量 | `ccType`、`ccUsers`、`userIds` |
| BPMN 扩展属性 | `ccUsers`、`ccType` |
| 枚举值 | `NODE` / `INST` / `MANUAL`、`PENDING` / `HANDLING` / `OVERDUE` / `DONE`、`REVOKED` / `INVALID` |
| 路由 | `#/cc`、`#/cc-sent` |
| 迁移脚本名 | `V6__cc_and_handle.sql` |

允许保留「CC」的地方只有两类：代码与接口标识；对外说明里作为英文缩写括注，例如「传阅（CC）」。除此之外界面上不出现「CC」。

## 09 现存不一致（已收敛）

以下两项在 v1.2 收敛，保留记录便于回溯：

| # | 位置 | 原状 | 本表口径 | 处理 |
|---|---|---|---|---|
| 1 | 我的传阅 · 逐条表头、展开行表头 | 类型 / 类型 · 节点 | 传阅类型 / 传阅类型 · 节点 | **已收敛**，与报表页「传阅类型分布」对齐 |
| 2 | 我的待阅 · 筛选 | 只有「未读 / 全部」 | 补「已读 / 已撤回」 | **已收敛**，后端 `mine` 支持 `UNREAD / READ / REVOKED / ALL` |

**已收敛：传阅类型列名。** 逐条表头与展开行表头均由「类型」改为「传阅类型」，展开行同时改「传阅类型 · 节点」；不再出现独立成列的「类型」二字。

**已收敛：我的待阅筛选。** 新增「已读」「已撤回」两项，顺序为未读 / 已读 / 已撤回 / 全部，默认仍为未读。口径要点：「已读」只含 `READ_ = 1` 且未撤回的记录；「已撤回」含撤回与失效两种（对应状态列「已撤回 / 已失效」标签），与「我的传阅」的状态筛选口径一致；「全部」不做过滤。

**已收敛：接收方列名。** 原先同一份数据在三个位置叫三个名字——逐条表头「收件人」、按流程表头「传阅给」、展开行「收件人」，现已统一为「待阅人」，与弹层字段、校验提示完全对齐；两处搜索占位符也一并改为「待阅人」。此后「传阅给」只作为句子里的短语出现（如本页说明、报表页「谁传阅给谁」），不再作为列名。

## 10 格式规则

| 项 | 规则 | 示例 |
|---|---|---|
| 引号 | 中文用「」，字段与 key 用反引号 | 「传阅」「`ccUsers`」 |
| 并列 | 用「·」不用「/」 | 传阅明细 · 待阅人 |
| 空值 | 统一 `—` | 办理时限 `—` |
| 时间 | `YYYY-MM-DD HH:mm` | 2026-11-09 14:30 |
| 必填 | 只用组件星号，文案里不写「必填」 | 待阅人 * |
| 按钮动词 | 发起传阅 / 撤回 / 取消，不用「确定」「提交」 | 发起传阅 |
| 提示语 | 「结果 + 影响」，不加感叹号 | 已撤回，对方将不再看到它 |
| 兜底提示 | 按实际动作命名，不用「操作成功 / 操作失败」 | 已传阅 / 撤回失败 / 加载失败 |

## 11 交付前自检

1. 界面里是否还有「抄送」「抄给」「抄送人」？源码与两处产物目录都要干净：

   ```
   rg -n "抄送|抄给|抄送人" frontend/src src/main/java src/main/resources/static/app
   ```

   注意：本文件把旧词作为「禁止出现」示例保留，属唯一例外；扫描时排除本文件。

2. 「待阅」是否只指传阅接收方？阅办的未开始状态必须是「待办理」。

3. 「我的待阅」与「我的传阅」是否各自只出现在对应视角的页面？

4. 三种类型标签是否都是「X 传阅」，没有残留「X 抄送」？

5. 撤回入口是否只在「本人 + 未读（或未提交结果）+ 未撤回」时出现？

6. 统计卡与列表是否同一口径：已读率分母排除撤回、失效；逾期实时推算。

7. 报表页签、图例、排行、空态是否全部叫「传阅」？

8. 改完后跑 `npm run build`，产物同步到 `src/main/resources/static/app` 与 `target/classes/static/app`；文案属前端资源，Ctrl+F5 强刷即可，只有 Java 侧提示改动才需要重启。
